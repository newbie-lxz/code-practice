# B站弹幕情感分析项目文件讲解

本文档用于说明本项目中各个文件和文件夹的作用，方便答辩、提交作业、后续修改和整理目录。

## 1. 项目整体作用

本项目主题是“B站学习区与生活区弹幕情感对比分析”。项目会完成以下流程：

```text
输入两个 BV 号
-> 爬取学习区和生活区弹幕
-> 清洗弹幕文本
-> 使用 jieba 分词、TF-IDF、字级 n-gram、HowNet/知网情感词典构造特征
-> 训练朴素贝叶斯、逻辑回归、SVM、随机森林
-> 选择表现最好的模型
-> 对真实弹幕进行正面/中性/负面分类
-> 人工复核低置信样本并继续学习
-> 输出 CSV 结果、图表和实验摘要
```

当前项目支持“四轮主动学习”：

- 第 1 轮：模型先分析一遍，并抽取最多 100 条不确定样本让人工标注。
- 第 2 轮：读取第 1 轮人工标注，再训练和分析。
- 第 3 轮：继续读取前两轮人工标注，再训练和分析。
- 第 4 轮：最终轮，不再提问，输出最终结果。

最终汇报和提交时，主要看 `final_round_4`。

## 3. `src/` 源代码目录

`src/` 是正式运行代码目录。项目真正执行时主要使用这里的 `.ipynb` 文件。

### `src/run_experiment.ipynb`

项目的一键运行入口，也是最重要的运行脚本。

运行命令：

```powershell
?? src\run_experiment.ipynb?? VS Code/Jupyter ??? Run All/????
```

它负责串起完整流程：

1. 询问实验名称。
2. 询问学习区 BV 号或视频链接。
3. 询问生活区 BV 号或视频链接。
4. 调用爬虫抓取弹幕。
5. 调用 `train_analyze.ipynb` 训练模型和分析弹幕。
6. 前三轮每轮询问最多 100 条人工复核样本。
7. 第四轮输出最终结果。
8. 自动把结果归档到 `results/实验名/` 和 `figures/实验名/`。

这个文件本身不负责具体建模，它更像“总调度器”。

### `src/run_experiment.ipynb`

由 `src/run_experiment.ipynb` 转换得到的 Notebook 版本。适合在 Jupyter 或 VS Code Notebook 里分块阅读代码。

注意：正式运行建议仍然用 `.ipynb` 文件，因为这个脚本包含终端输入交互，Notebook 里运行不一定更方便。

### `src/crawler_bilibili.ipynb`

B站弹幕爬虫脚本。它负责：

1. 根据 BV 号请求 B站视频信息接口。
2. 获取视频的 `cid`。
3. 根据 `cid` 请求 XML 弹幕接口。
4. 解析 XML 中的弹幕文本。
5. 保存为 CSV。

输出字段包括：

- `partition`：分区，例如学习区、生活区。
- `bvid`：视频 BV 号。
- `title`：视频标题。
- `view_count`：播放量。
- `like_count`：点赞量。
- `coin_count`：投币量。
- `favorite_count`：收藏量。
- `reply_count`：评论量。
- `danmaku_count`：弹幕总量。
- `text`：弹幕文本。

如果 B站接口风控导致请求失败，可以在 `HEADERS` 中补充浏览器 Cookie。

### `src/crawler_bilibili.ipynb`

`crawler_bilibili.ipynb` 的 Notebook 版本，方便逐块查看爬虫逻辑。

### `src/train_analyze.ipynb`

项目最核心的分析脚本。它负责：

1. 读取训练数据。
2. 读取真实爬取弹幕。
3. 清洗文本。
4. 使用 `jieba` 中文分词。
5. 读取 HowNet/知网情感词典。
6. 构造词级 TF-IDF 特征。
7. 构造字级 2-4gram TF-IDF 特征。
8. 构造情感词典特征，例如正面词数量、负面词数量、情感分数等。
9. 训练四种模型：
   - 朴素贝叶斯。
   - 逻辑回归。
   - SVM。
   - 随机森林。
10. 比较模型准确率和 F1。
11. 选择最优模型。
12. 对全部真实弹幕预测情感。
13. 根据模型概率、词典分数和人工规则修正最终标签。
14. 导出正面、中性、负面弹幕。
15. 生成分区统计、模型报告、混淆矩阵和图表。
16. 抽取低置信/冲突样本供人工复核。

它是决定分类结果准确不准确的关键文件。

### `src/train_analyze.ipynb`

`train_analyze.ipynb` 的 Notebook 版本。适合阅读建模流程，尤其是查看每个函数的作用。

### `src/make_sample_data.ipynb`

演示样例数据生成脚本。如果 `data/danmu_sample_5000.csv` 不存在，程序可以自动调用它生成课堂演示用训练样本。

它生成的是模拟弹幕数据，不是真实 B站弹幕。真实实验主要依赖 `crawler_bilibili.ipynb` 爬取的数据。

### `src/make_sample_data.ipynb`

`make_sample_data.ipynb` 的 Notebook 版本。

## 4. `data/` 数据目录

`data/` 用来保存训练数据、真实爬取弹幕、情感词典和人工反馈。

### `data/danmu_sample_5000.csv`

训练样例数据。它用于训练初始模型，里面包含：

- `partition`：分区。
- `bvid`：视频或样例编号。
- `text`：弹幕文本。
- `label`：人工标注标签。

标签规则：

- `1`：正面。
- `0`：中性。
- `-1`：负面。

这个文件对模型训练很重要。如果没有它，程序会自动生成演示数据，但真实效果会受影响。

### `data/experiments/`

每次运行实验时，爬虫保存原始弹幕的地方。

目录结构示例：

```text
data/experiments/
  experiment_20260528_145329/
    raw_bilibili_danmu.csv
```

其中：

- `experiment_20260528_145329`：某一次实验。
- `raw_bilibili_danmu.csv`：这次实验爬到的原始弹幕。

### `data/experiments/*/raw_bilibili_danmu.csv`

真实爬取的弹幕数据。它是每次实验的输入数据，后续模型会对它进行预测和分析。

这个文件一般不要手动改，除非你明确知道自己要清洗或替换爬虫数据。

### `data/sentiment_lexicon/hownet_positive.txt`

正面情感词典。项目会把它和代码里的兜底词表合并成 `POS_WORDS`。

它用于：

- 计算正面词数量。
- 计算词典情感分数。
- 作为机器学习模型的辅助特征。
- 辅助最终情感标签修正。

### `data/sentiment_lexicon/hownet_negative.txt`

负面情感词典。作用和正面词典类似，只是用于负面词。

注意：代码里会临时剔除一些容易误伤的单字词，例如 `好`、`强`、`牛`、`水`，避免短弹幕被错误分类。

### `data/feedback/README.md`

人工反馈目录说明文件。它解释人工标注数据应该怎么放、怎么被程序读取。

### `data/feedback/README.pdf`

`data/feedback/README.md` 的 PDF 版本。

## 5. `results/` 结果目录

`results/` 保存每次实验的 CSV、报告和文本摘要。它是查看模型分析结果的主要位置。

目录结构示例：

```text
results/
  experiment_20260528_145329/
    round_1/
    round_2/
    round_3/
    final_round_4/
```

含义：

- `experiment_20260528_145329`：一次完整实验。
- `round_1`、`round_2`、`round_3`：前三轮主动学习结果。
- `final_round_4`：最终结果，汇报时主要看这里。

每个轮次目录中常见文件如下。

### `analysis_summary.md`

自动生成的实验摘要。包含：

- 最优模型。
- 模型准确率和 F1。
- 训练样本数。
- 人工反馈样本数。
- 分区情感比例。
- 简要建议。

### `analysis_summary.pdf`

`analysis_summary.md` 的 PDF 版本，方便直接提交或阅读。

### `classification_report.txt`

最优模型的文本版分类报告。里面记录模型名称、训练数据、预测数据、训练样本数、词典数量和模型指标。

### `classification_report_full.csv`

更完整的分类指标表，通常包含每个类别的：

- precision。
- recall。
- f1-score。
- support。

用于更细致地查看正面、中性、负面分别表现如何。

### `confusion_matrix.csv`

混淆矩阵数据。它记录模型把真实标签预测成各类标签的数量。

例如可以看出：

- 负面是否经常被预测成中性。
- 中性是否经常被预测成正面。
- 正面是否经常被预测成负面。

### `confidence_summary.csv`

按分区和情感类别统计模型置信度。可以用来观察：

- 学习区正面弹幕平均置信度。
- 生活区负面弹幕平均置信度。
- 哪些类别模型比较不确定。

### `conflict_samples.csv`

词典和模型意见冲突的样本。

例如：

- 词典偏正，但模型偏负。
- 词典偏负，但模型偏正。
- 模型判中性，但词典有明显情感词。

这个文件适合人工检查模型错误。

### `danmu_predicted.csv`

最重要的预测结果文件。每一条弹幕都有一行，包含：

- 原始文本。
- 清洗后的文本。
- 分区。
- BV 号。
- 模型原始预测。
- 最终预测标签。
- 正面/中性/负面概率。
- 词典情感分数。
- 是否被人工标签覆盖。

如果你想逐条检查分类准不准，优先看这个文件。

### `experiment_summary.txt`

本轮实验的整体摘要，记录：

- 输入视频。
- 原始弹幕路径。
- 采集总量。
- 学习区和生活区采集量。
- 训练数据路径。
- 最优模型。
- 输出目录。
- 图表目录。

它适合快速回顾某一轮实验做了什么。

### `iteration_comparison.csv`

当前轮和上一轮实验结果的对比。可以看主动学习之后情感比例有没有变化。

不是第一轮时才会出现，所以数量可能比其他文件少。

### `low_confidence_samples.csv`

模型低置信样本。也就是模型最不确定的弹幕。

这些样本适合人工标注，因为标它们通常能更有效提升下一轮模型效果。

### `model_metrics.csv`

四个机器学习模型的对比结果。通常包含：

- 模型名称。
- accuracy。
- macro-F1。

程序会根据指标选择最优模型。

### `positive_comments.csv`

最终判为正面的弹幕集合。适合人工抽查正面分类是否合理。

### `negative_comments.csv`

最终判为负面的弹幕集合。适合人工抽查负面分类是否合理。

### `neutral_comments.csv`

最终判为中性的弹幕集合。适合检查中性是否过多或过少。

### `partition_sentiment_stats.csv`

学习区和生活区的情感占比统计。它是汇报里最重要的结果表之一。

通常用来回答：

- 学习区正面、负面、中性分别占多少。
- 生活区正面、负面、中性分别占多少。
- 两个分区的情绪分布有什么差异。

### `review_samples.csv`

人工复核样本。前三轮会让你在终端对这里的样本填写标签。

标签规则：

- `1`：正面。
- `0`：中性。
- `-1`：负面。

程序下次运行会自动读取历史 `review_samples.csv`，把你标过的样本加入训练集。

### `video_sentiment_stats.csv`

按视频统计情感比例。它比 `partition_sentiment_stats.csv` 更细，能看到每个 BV 号自己的情感分布。

## 11. 哪些文件可以删除

以下文件或目录不是程序运行必需：

- `annotated_code/`：只是阅读代码用。
- `*.ipynb`：Notebook 阅读版，正式运行不需要。
- `*.pdf`：说明文档或摘要 PDF，正式运行不需要。
- 旧的 `results/experiment_xxx/`：旧实验结果，不想保留可以删除。
- 旧的 `figures/experiment_xxx/`：旧实验图表，不想保留可以删除。
